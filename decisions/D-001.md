Decision Record D001
Use an External Mapping and Geocoding API Instead of Building Custom Route Computation
Decision
Delegate distance matrix computation, geocoding, and base routing calculations to an external mapping API (OpenStreetMap or Mapbox) rather than building this logic in house.
Alternative Considered
Build a custom distance and routing engine using raw map data and an in house graph based pathfinding algorithm.
Rationale
A custom engine would consume most of the semester on low level geospatial computation rather than the project's actual focus areas: stateful workflow management, constraint enforcement, and dispatch business logic. An external API gives reliable, production grade distance and time data with minimal setup effort, keeping development scope focused on orchestration and business logic (see also Feasibility, Section 10 to 25).
Consequence Accepted
The team depends on external API availability, rate limits, and potential usage costs. If the API becomes unavailable or costs exceed free tier limits, route computation would need throttling, caching, or a fallback provider. This dependency is a known risk to monitor going forward.
